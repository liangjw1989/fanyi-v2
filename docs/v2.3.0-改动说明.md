# v2.3.0 改动说明

针对反馈的四个问题：

## 1. 输出格式不自由、多数变成 HTML
PDF/DOCX 现在默认输出 Word。「原文译文对照」新增**上下排列**模式
（原文一段在上、译文紧随其下，仿搜狗翻译），原有左右分栏保留，共 6 种输出。

## 2. Word 排版不像原文 —— 关键修复
**根因**：`render-docx` 遇到 `container`（PDF 双栏）会直接拍平成单栏。

**修复**：用收集器栈把各栏内容放进**独立节**，并设置 `column.count`，
真正生成 `<w:cols w:num="2">`。

**用真实 docx 库验证**（`test/docx-real.test.js`）：

| 检查项 | 结果 |
|---|---|
| 双栏 `w:cols w:num="2"` | ✓ |
| 多节 `w:sectPr=2` | ✓ |
| 15pt 标题字号 | ✓ |
| 10.5pt 正文字号 | ✓ |
| 居中对齐 | ✓ |
| 两端对齐 justify | ✓ |
| 首行缩进 21pt → 420 | ✓ |
| 表格 3 列 × 2 行 | ✓ |

## 3. 选 PDF 还要再点一次下载
现在**自动弹出打印对话框**，直接「另存为 PDF」即可。

## 4. 所有译文表格都不对 —— 根因修复
**根因**：`detectTable` 把两栏页面的正文误判成「两列大表」，
随后在列数变化处不断断开，一张表被切成几十个「2 行碎片」。
（实测某论文输出 20 个表格，其中 19 个是 2 行碎片 + 1 个 39 行巨表）

**修复（两层）**：

1. `layout.js` 新增**正文防误判**三道否决：句读结尾长片段比例 > 20%、
   单格 > 42 字符、行数 > 80。原则是宁可把表格当正文，也不把正文当表格。
2. `pdf-extract.js` 新增**碎片合并**：列数差 ≤ 2、中间没有正文行或表格
   标题行时，把相邻碎片合回一张表（纯数字行不阻止合并）。

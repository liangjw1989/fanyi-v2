# PDF 版式还原的技术路线（研究结论与实施方案）

> 写这份文档的原因：PDF 翻译"保持原排版"连续多轮未达标。这里把根因、
> 业界做法、三条可选路线和具体实施方案写清楚，避免继续在死路上反复试。

---

## 一、为什么"PDF → 结构重建"这条路走不通

### PDF 的本质

PDF 不是文档，是**一张纸上画了一堆字形**。里面只有：

```
"在坐标 (166.4, 329.7) 画这几个字，字号 9.96，字体 f12"
```

**没有**段落、没有栏、没有表格、没有"这是标题"的信息。

### 我们需要做的事

```
字形坐标 → 猜分行 → 猜分栏 → 猜段落 → 猜表格 → 重新排版成 Word/HTML
             ↑ 每一步都是启发式，每一步都可能错，且错误会累积
```

### 实测踩到的具体坑（都是真实故障，不是假设）

| # | 现象 | 根因 |
|---|---|---|
| 1 | 正文与版权声明逐段交替 | 期刊「宽正文栏 + 窄左边注栏」，`groupLines` 只看 y 就跨栏合并成一行，文本变成 `"Licensee MDPI, Basel, Switzerland.are not discussed"` |
| 2 | 边注栏永远切不开 | 真实空档只有 **13pt**（x1=153 → x=166），比"空档 ≥20pt"的门槛还小 |
| 3 | 拆行逻辑从不执行 | 找到了一条**错误的走廊**（x≈404，在正文内部），走廊分支先命中断言 |
| 4 | 一页炸出 **17 个区域** | `for (const l of midSpans) out.push(...)` 每条通栏行单独成区；另一处 `l.y0 >= splitAt` 在 splitAt 之后**每行都切一刀** |
| 5 | 表格识别结果 1 → 0 | 拆行逻辑把表格行也拆了（单元格之间本来就是大空白） |
| 6 | 占位符变成 `#P0 ##` 垃圾 | 腾讯云把 `##P0##` 输出成 `## P0 ##`（带空格），旧解码正则不允许字母与数字间有空格 |

**结论**：这类复杂期刊版式（MDPI：宽正文 + 窄边注 + 通栏表格/图注/公式 + 页眉页脚），
靠启发式**不可能稳定做对**。每修一处就破坏另一处 —— 这是路线问题，不是 bug 多。

## 二、业界是怎么做的

### WPS 官方承认需要人工微调

[WPS 365 译后版式还原](https://365.wps.cn/content/50cf15462db64b868b5f4d2cb34d550c.html)原文：

> 针对翻译后可能出现的**局部版式偏差**，系统提供**智能微调面板**，
> 支持**手动优化**段落间距、图片偏移或文本框适配

即：**连 WPS 也不敢承诺 100% 自动还原**，它交付的是「自动 + 人工微调」。

### 真正的技术分野

| 输入 | 做法 | 保真度 |
|---|---|---|
| **Word / Office 源文件** | 直接改 XML 里的文字节点 | **100%**，无需任何推断 |
| **PDF 源文件** | ① 重建结构（我们现在的做法） | 有损，复杂版式必错 |
| | ② **原位替换文字**（业界主流） | **100%**，不需要推断 |

**关键洞察**：PDF 的版式**不用还原**，因为它本来就在那儿。
正确做法是**保留原 PDF，只把文字换掉**：

```
原 PDF（几何完美） → 每个文字位置涂白 → 原位置写译文（嵌入中文字体子集） → 保存
```

这样：
- 版式 100% 保真 —— 图、表、公式、页眉页脚全部原封不动
- 文字**可选中、可搜索** —— 因为是真正的文字，不是图片
- **完全不需要猜分栏、猜表格** —— 这是它最大的价值

## 三、三条路线对比（现状与取舍）

| 路线 | 版式保真 | 文字可选中 | 可编辑 | 实现状态 |
|---|---|---|---|---|
| A. 结构重建 → Word/HTML | 启发式，复杂版式会错 | ✅ | ✅ | **已实现**（v2.5.0） |
| B. 原图叠加 → 图片型 PDF | **100%**（背景就是原页） | ❌ | ❌ | **已实现**（v2.5.0） |
| C. **原位替换文字** → 矢量 PDF | **100%** | ✅ | 一般 | **待实现**（本文第四节） |

- **A** 适合：Word 源文件、版式简单的 PDF
- **B** 是过渡方案：能立刻解决"版式别乱"，代价是不可选中、文件大
- **C** 是**真正的目标**：同时满足版式保真 + 可选中

## 四、路线 C 的实施方案（可选中 + 原排版）

### 4.1 依赖

| 库 | 作用 | 大小 | 来源 |
|---|---|---|---|
| `pdf-lib` | 打开已有 PDF、在页面上绘制、嵌入字体子集 | 513 KB | npmmirror |
| `@pdf-lib/fontkit` | 解析 TTF/OTF 并做**字形子集化** | 741 KB | npmmirror |
| 中文字体 | 提供字形轮廓 | 9~16 MB（单一 TTF） | 见 4.2 |

**子集化的意义**：`doc.embedFont(bytes, { subset: true })` 只把**实际用到的字**写进 PDF。
一篇 22 页论文大约用到 800~1200 个不同汉字，嵌入后通常只有 **150~400 KB**，
不会因为字体 10MB 就让输出膨胀。

### 4.2 字体策略（唯一的外部依赖）

需要**可再分发**的中文字体。三个选项，按优先级：

1. **用户本机字体**（推荐，零版权风险、零网络依赖）
   界面上让用户选一次字体文件，例如 Windows 自带：
   ```
   C:\Windows\Fonts\simhei.ttf   9.3 MB  ← 单一 TTF，最省事
   C:\Windows\Fonts\simfang.ttf 10.1 MB
   C:\Windows\Fonts\simkai.ttf  11.2 MB
   C:\Windows\Fonts\Deng.ttf    15.6 MB
   ```
   用 `<input type="file" accept=".ttf,.otf">` 读取 → `File.arrayBuffer()`
   → 直接交给 `embedFont`。字体**不离开用户机器**，仓库里也不用放字体。

   注意：`msyh.ttc` / `simsun.ttc` 是**字体集合**（TTC），fontkit 需要选 face，
   优先引导用户选 `.ttf` 单文件字体。

2. **随仓库放开源字体**（体验最好，但要 9MB+ 仓库体积）
   Noto Sans SC / 思源黑体（OFL 授权，可再分发）。
   本次实测：`fonts.gstatic.com`、jsDelivr 均不可达；
   npmmirror 的 `@fontsource/noto-sans-sc` 只有 **1188 个 woff2 分片**
   （按 unicode-range 切分），无法直接得到单一 TTF。

3. **云函数端转换**（最稳，但要改后端）
   在腾讯云函数里用 Python + `fontTools` 做子集化，前端只传译文，
   后端返回已嵌入字体的 PDF 片段。

### 4.3 算法（关键在"塞得下"）

```
输入：原 PDF 字节、每页的 (文字块 bbox, 原文, 译文, 原字号)
对每一页：
  1. pdf-lib: page.drawRectangle({ x, y, width, height, color: white })  // 涂白原文
  2. 计算字号：
       size = 原字号
       用原字号排版译文 → 若行数超出 bbox 高度 → size *= 0.94，重试（最多 6 次）
       下限 0.6×原字号（再小就看不清了）
  3. 按 bbox 宽度折行（中文按字断行，西文按词断行）
  4. page.drawText(line, { x, y, size, font })
  5. 若仍放不下：允许溢出到相邻空白行（PDF 里垂直方向通常有余量）
输出：doc.save()
```

**为什么中文通常放得下**：同样内容，中文译文的字数是英文的 40~60%，
在同样的 bbox 里往往更省空间。真正需要缩字号的是"英译中且栏很窄"的情况。

**坐标翻转**：pdf.js 的 y 轴向下，pdf-lib 的 y 轴向上（原点左下）。
`pdfY = pageHeight - jsY - lineHeight`，这个换算必须做对，否则整页错位。

### 4.4 已知限制（必须告知用户）

- 表格里很窄的单元格，译文可能放不下 → 会缩字号，极小字号可读性差
- 原文是图片里的文字（扫描件）→ 无文字层，此方案无效（需 OCR）
- 译文比原文长很多的语种对（中译英）容易溢出
- 加密 / 有权限限制的 PDF 可能无法保存

## 七、一句话总结

> 之前所有努力都在做「**从 PDF 反推版式再重建**」，这条路对复杂期刊版式注定不稳。
> 真正的解法是「**不动版式，只换文字**」—— 原 PDF 几何保留，涂白原文、
> 在原位写译文、嵌入中文字体子集。版式 100% 保真且文字可选中。

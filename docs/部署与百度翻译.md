# 部署指南：百度翻译 + 腾讯云函数 + GitHub Pages

本文档解决三件事：
1. 怎么申请百度翻译（100 万字符终身免费）
2. 怎么把新版云函数（腾讯云 + 百度 + DeepSeek 三引擎）部署上去
3. 怎么开启 GitHub Pages，让二维码/链接可以直接给别人用

---

## 一、申请百度翻译（约 5 分钟）

1. 打开 <https://fanyi-api.baidu.com/> → 右上角 **登录**（可用百度账号）
2. 进入 **管理控制台** → **总览** → 点 **立即使用** / **开通通用文本翻译**
3. 选择 **通用文本翻译**（个人认证即可，免费）
4. 回到 **管理控制台 → 开发者信息**，记下这两项：

   | 名称 | 用途 |
   |---|---|
   | **APP ID** | → 环境变量 `BAIDU_APP_ID` |
   | **密钥** | → 环境变量 `BAIDU_APP_KEY` |

5. 免费额度：**通用文本翻译 100 万字符 / 终身**（QPS 限制为 1，即每秒 1 次；函数里已做节流）

> 关于质量：百度的学术/医学语料比通用 MT 好，实测在"数字、单位、专业名词"上更稳。
> 但**它仍然只是机器翻译**，不要指望它对论文长句的理解超过 DeepSeek。
> 建议用法：**普通模式用百度**（省钱、够用），**精修稿用 DeepSeek**。

---

## 二、部署新版云函数

新版函数文件在 `deploy/云函数.js`（已随仓库上传），相比你原来的版本：

| 变化 | 说明 |
|---|---|
| ➕ 新增 `baidu` 引擎 | 请求里 `engine: 'baidu'` 即走百度 |
| ➕ **标记复核** | 翻译后校验 `⟦n⟧`/`⟦P0⟧`/`⟦T1⟧` 是否完整；缺了就自动换引擎重试，避免"符号丢了却显示成功" |
| ➕ **自动降级** | 百度/DeepSeek 失败自动用腾讯云兜底，不让你白等 |
| ➕ **CORS 响应头** | 网页端（`file://` 或 GitHub Pages）可直接调用，不会再被浏览器拦 |
| ➕ **健康检查** | 不带 `text` 请求时返回"已配置引擎"，对应界面上的「测试连接」 |
| 🔧 修正 DeepSeek 提示词 | 去掉旧的 `[[TITLE]]`/`[LEFT]` 那套标记（那是"让 AI 重排版"的做法，会导致排版走样）。现在明确要求：**只翻译、保留 ⟦n⟧ 与占位符、不要重排** |
| 🔧 `max_tokens` 16000 → 8000 | 8000 足够单段翻译，避免超长导致截断或计费浪费 |

### 部署步骤

1. 腾讯云 → **云函数 SCF** → 找到你现有的函数
2. 打开 `index.js`（或你命名的主文件）→ **全选删除** → 粘贴 `deploy/云函数.js` 的全部内容
3. **函数配置 → 环境变量**，补齐这几项（值只填在腾讯云，不要写进代码）：

   | 变量名 | 值 |
   |---|---|
   | `TMT_SECRET_ID` | 你已有的腾讯云 SecretId |
   | `TMT_SECRET_KEY` | 你已有的腾讯云 SecretKey |
   | `BAIDU_APP_ID` | 第一节拿到的 APP ID |
   | `BAIDU_APP_KEY` | 第一节拿到的密钥 |
   | `DEEPSEEK_API_KEY` | 你已有的 DeepSeek Key |

4. **部署**（保存并部署）
5. 回到前端 → `⚙️ 翻译服务设置` → 点 **测试连接**，应看到：

   ```
   服务正常。已配置引擎：tencent, baidu, deepseek
   ```

   > 少了哪个引擎名，就是对应环境变量没配上。

6. 依赖：函数需要 `axios`（腾讯云翻译签名用）。若报 `Cannot find module 'axios'`，
  在 SCF 控制台的 **函数代码 → 依赖管理** 里添加 `axios`，或用层（Layer）挂载。

### 前端怎么切引擎

上传文件后，每个文件后面有三个下拉框，中间的引擎选项现在有三个：

```
普通翻译（腾讯云）
普通翻译（百度 · 免费额度大）
AI 智能翻译（DeepSeek）
```

选好再点「翻译」即可。翻译记忆是按"文本内容"缓存的，换引擎也能复用已有译文。

## 三、开启 GitHub Pages（30 秒，让二维码可用）

**这一步必须手动**（GitHub 的 Pages 创建接口要求带访问令牌鉴权，我用你的公开仓库试过，返回 401）。

### 步骤

1. 打开 <https://github.com/liangjw1989/fanyi-v2/settings/pages>
2. **Source** 选 `Deploy from a branch`
3. **Branch** 选 **`main`**，目录选 **`/ (root)`**
4. 点 **Save**
5. 等 1~2 分钟（首次部署），刷新该页面，顶部会出现：

   ```
   Your site is live at https://liangjw1989.github.io/fanyi-v2/
   ```

### 开通后你会得到

| 用途 | 地址 |
|---|---|
| 在线使用 | `https://liangjw1989.github.io/fanyi-v2/` |
| 手机扫码 | 页面里那个二维码会自动指向这个地址，**手机扫码即可打开** |

### 二维码相关提醒

- 二维码内容是**当前页面地址**（`location.href`）：
  - 本地双击 `index.html`（`file://`）→ 二维码指向本地路径，**手机扫了打不开**
  - 从 Pages 地址打开 → 二维码指向网址，**手机扫码可直接用** ✅
- 微信里打开时，代码会提示"点击右上角 → 在浏览器中打开"（微信内选文件受限）
- 想做到"扫码即用、不用填地址"，把云函数地址填进仓库根目录的 `config.js`：

  ```js
  root.LINGYI_CONFIG = {
    API_URL: 'https://你的云函数地址',
  };
  ```

  > 权衡：`config.js` 是公开的，填上之后**陌生人也可能调用你的额度**。
  > 由于密钥都在云函数环境变量里，最坏情况只是额度被用掉，不会泄露凭据。
  > 如果介意，可以让函数加一层"来源校验"或每日调用上限。

## 四、验证清单

部署完成后，按这个顺序验收：

```bash
# 1) 本地离线自检（不联网、不花钱）
cd 最终\repo
node test\selfcheck.js

# 2) 模拟后端，验证界面交互
node test\mock-server.js
```

然后在浏览器里（Pages 地址或本地 `index.html`）：

| 步骤 | 期望结果 |
|---|---|
| 翻译服务设置 → 测试连接 | `服务正常。已配置引擎：tencent, baidu, deepseek` |
| 上传一篇论文 .docx → 引擎选「普通翻译（百度）」→ 翻译 | 提示里"套用术语/保护符号"有数字，译文写入，排版不变 |
| 同一文件再译一次 | 提示"记忆复用"等于总片段数，接口调用 0 次 |
| 引擎换「AI 智能翻译（DeepSeek）」→ 翻译 | 质量更好；若 DeepSeek 超时，会自动用腾讯云兜底而不是直接失败 |
| 输出格式逐个试 | Word 版式 1:1；中英对照左右对应；PDF 用打印对话框导出 |
| 手机扫二维码 | 能打开同一个在线页面 |

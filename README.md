# 灵译 LingYi · 保版式文档翻译

> 把文献 / 科研论文 / 报告翻译成其他语言，**排版一点不变**：
> 段落、字号、对齐、首行缩进、表格列、双栏、图片、参考文献格式全部保留。

版本 **v2.1.0** ｜ © 2026 灵译 LingYi ｜ 个人使用免费，商业使用需授权（见 [LICENSE](LICENSE)）

## 一、它解决什么问题

常见做法是 `文件 → 压成一整块纯文本 → 丢给翻译接口 → 让大模型"重新排版"`，结果排版必然走样。
本项目的思路是：**不重建排版，只在原有版式骨架上替换文字。**

```
文件 → ① 结构化抽取（版式骨架 IR）
        Word：段落/标题/表格/图片 + 字号/加粗/对齐/缩进/合并单元格
        PDF ：文字坐标 → 行聚类 → 分栏检测 → 段落合并 → 表格识别
     → ② 翻译记忆命中？ 命中就直接复用（0 次接口调用）
     → ③ 术语库：把术语换成 ⟦T1⟧ 占位符 → 强制统一译名
     → ④ 符号保护：数字/单位/上下标/希腊字母/参考文献编号 → ⟦P0⟧ 占位符
     → ⑤ 调用翻译引擎（腾讯云 / DeepSeek）
     → ⑥ 还原占位符 + 校验，按原骨架回填
     → ⑦ 输出 Word / HTML / 双栏对照 / 纯文本
```

**为什么表不会再少列、符号不会再乱**：表格每个单元格是独立片段；`P<0.001`、`95%CI 1.030~1.074`、
`kg/m²`、`×10⁶/mL`、`β`、`χ²`、`[1,2]`、`图1`、`表2` 等会被"挖出来"换成占位符，
翻译引擎根本没机会改它们，翻完再原地填回。

## 三、使用

1. 浏览器打开 `index.html`（Chrome / Edge）。
2. 点上传区域选文件（PDF / .docx / .txt / .md / 图片）。
3. 点 **⚙️ 术语库 · 翻译记忆 · 符号保护**：
   - 勾选 **符号保护**（默认开，强烈建议保持）
   - 勾选 **翻译记忆**（默认开）
   - 点 **📚 载入学术常用术语** 一键导入内置术语库，也可自己粘贴/导入
4. 选语言、模式、输出格式 → 点「翻译」。
   - 输出 **Word**：版式 1:1，完成后自动下载
   - 输出 **PDF**：打开排版页，在打印对话框选「另存为 PDF」
   - 输出 **中英对照**：左右双语对照网页
5. 「已完成的文档」里可再次预览 / 转存 HTML / 下载。

> 首次使用需联网（从 CDN 加载 pdf.js、mammoth、docx、tesseract）。
> 把这些库放进 `vendor/` 目录即可完全离线运行（翻译服务本身仍需联网）。

## 四、密钥放在哪里（安全说明）

> **前端程序里没有任何密钥。** 这是刻意的架构设计，不是巧合。

| 内容 | 存放位置 | 会不会上传到 GitHub |
|---|---|---|
| 腾讯云 `TMT_SECRET_ID` / `TMT_SECRET_KEY` | 云函数**环境变量** | ❌ 不会 |
| DeepSeek `DEEPSEEK_API_KEY` | 云函数**环境变量** | ❌ 不会 |
| 云函数 URL | 前端「翻译服务设置」或 `config.js` | ✅ 会（**它不是密钥**，只是地址） |

- 前端只知道一个"云函数地址"，它没有密钥。地址即使被看到，对方也只能**调用**，拿不到你的凭据。
- 真正的风险只是"被陌生人白用额度"。要降低风险，可以：
  1. 在公开仓库里把 `config.js` 的 `API_URL` **留空**，让使用者填自己的地址；
  2. 在云函数里加来源校验（只允许你的域名）和每日调用上限；
  3. 定期在腾讯云控制台轮换密钥（轮换只改环境变量，前端不用动）。

详见 [docs/后端接口约定.md](docs/后端接口约定.md)：里面有完整的环境变量清单、
请求/响应协议，以及一份可直接部署的云函数参考实现。

**结论：你可以放心把本项目上传 GitHub —— 里面没有密钥。**
## 五、怎么上传到 GitHub

> **先说结论：GitHub 网页版不能上传文件夹。**
> 网页上只能一次选多个**文件**；文件夹要靠 Git 客户端，或手工建目录再逐个传（很麻烦）。
> 所以推荐用本仓库自带的两个批处理文件。

> **本机实测（2026-10-06）**：`github.com` 的 HTTPS 被拦（超时），但 **SSH 通道可用**
> （`github.com:22` 握手成功）。所以这台机器应当**走 SSH**，不需要翻墙。
> 详见 `docs\上传排错.md`。

### 方式零：走 SSH（本机最省事，推荐）

1. 装 Git：双击 `install-git.bat`（HTTPS 被拦，winget 会失败；脚本会改走镜像）。
2. 双击 `setup-github-ssh.bat`：自动生成密钥、测试连接、把公钥复制到剪贴板。
3. 在能打开 github.com 的网络（手机热点 / VPN）访问
   `https://github.com/settings/ssh/new`，粘贴公钥并保存。
4. 在 repo 目录执行：
   ```bash
   git init
   git branch -M main
   git add -A
   git commit -m "feat: 保版式文档翻译 v2.1"
   git remote add origin git@github.com:你的用户名/仓库名.git
   git push -u origin main
   ```

打不开 github.com 加公钥时，改用 Gitee：双击 `upload-to-gitee.bat`
（gitee.com 本机实测可达），效果与 GitHub 等价。

### 方式一：一键脚本（HTTPS 可用时）

1. 先装 Git（装了可跳过）：双击 **`install-git.bat`**（或去 https://git-scm.com/download/win 手动装）。
2. 用记事本打开 **`upload-to-github.bat`**，把开头的两行改成你自己的信息：
   ```
   set GIT_USER_NAME=你的名字或昵称
   set GIT_USER_EMAIL=你的邮箱@example.com
   ```
3. 到 GitHub 网页新建一个**空仓库**（不要勾 Add README / .gitignore / license），复制它的地址
   （形如 `https://github.com/你的用户名/仓库名.git`）。
4. 双击 **`upload-to-github.bat`**，按提示粘贴仓库地址。首次会要求登录 GitHub，授权后自动完成
   初始化、提交、推送。

### 方式二：GitHub Desktop（图形界面，适合不想敲命令）

1. 到 https://desktop.github.com 下载安装，登录 GitHub 账号。
2. `File → Add local repository`，选择本项目文件夹（如 `最终\repo`）。
3. 若提示"不是仓库"，点 `create a repository`。
4. 左下角填提交说明 → `Commit to main` → 右上角 `Publish repository`（可勾选 Private）。

### 方式三：网页手工上传（不推荐）

新建仓库时先建好 `src`、`test` 等目录，然后逐个 `Add file → Upload files`。
因为网页**无法一次性保留目录结构**，39 个文件要传很多次，只适合应急。

### 上传后开 GitHub Pages（让别人直接打开就能用）

仓库 → `Settings` → `Pages` → Source 选 `main` / `/(root)` → Save。
稍等片刻访问 `https://你的用户名.github.io/仓库名/` 即可（页面会自动加载 `index.html`）。

> 注意：应用运行时需联网从 CDN 加载 pdf.js、mammoth、docx 等库；
> 想离线使用就把这些库放进 `vendor/` 目录一起上传。

## 六、关于"保护代码"的实话

**必须坦白：只要代码运行在浏览器里，就无法真正防止别人查看源码。**
任何人按 F12 都能看到代码；公开仓库的历史提交同样可见；混淆只能挡住外行。

本项目实际采用的保护方式：

| 手段 | 作用 |
|---|---|
| [LICENSE](LICENSE) 明确"个人免费 / 商业需授权 / 禁止去标识再分发" | 法律依据：别人拿去商业使用时你有明确追责基础 |
| 每个源文件头部版权声明 | 便于举证对方"明知故犯" |
| `build.js` 在产物里写入版权水印与构建指纹（sha256） | 可证明某份部署是否来自官方构建 |
| 版权声明（页脚 + 构建横幅） | 提醒使用者尊重许可 |

如果你**确实需要技术层面的防护**，只有一条路有效：

> 把核心逻辑（解析 + 版式还原 + 术语保护）搬到服务端（Cloudflare Worker / 云函数），
> 前端只做上传下载。这样别人拿到前端也拿不到引擎。

不建议做的：花力气搞重度混淆。它会让代码难以维护，却挡不住真正想抄的人。

## 七、翻译功能说明（关于"不再依赖腾讯云 / DeepSeek"）

**结论：纯离线、且达到投稿级质量的翻译，在浏览器里做不到。** 原因很实在：

- 最小的可用神经翻译模型（Argos / Marian）也有几百 MB，浏览器要下载、要跑，
  一篇论文在 CPU 上要很久，质量还明显不如现有引擎；
- 规则/词典式离线翻译只能做到"逐词直译"，读得懂但不像人话，**不适合文献与论文**。

因此本项目在**保留云引擎**的前提下，把你真正疼的地方用工程手段解决掉：

1. **符号与上下标**：由程序保护，不交给引擎（这是论文翻译最容易出错、也最不可接受的部分）；
2. **术语一致**：内置 + 自定义术语库，强制统一译名（DFI、PR、BMI、Kruskal-Wallis…）；
3. **省成本**：翻译记忆让同一内容只翻一次；改稿重译只翻改动段落；
   同一批文献里的重复段落零成本复用。
4. **可预期**：术语库与翻译记忆都能导出备份、导入复用，长期积累成你自己的资产。

后续如果想彻底摆脱外部服务，可选的路线（按性价比排序）：

| 路线 | 说明 | 代价 |
|---|---|---|
| 自建翻译服务 | 服务器上跑开源模型（如 opus-mt / NLLB），前端调自己的接口 | 需要一台带 GPU 的机器 |
| 换成免费公共接口 | LibreTranslate 等公开实例 | 有速率限制，学术质量一般 |
| 用户自带密钥（BYOK） | 使用者在设置里填自己的 Key | 成本转移到用户，需要小改造 |

## 九、已知边界

- **扫描件 PDF**（整页图片、无文字层）：请改用图片模式走 OCR。
- **.doc 老格式**：先在 Word/WPS 里另存为 `.docx`。
- **复杂公式**：PDF 没有段落语义，按坐标还原，多行公式会有误差。
- **加密文档**：无法解析。
- 译文由第三方翻译服务生成，专业内容请自行核校（程序保证的是**符号与版式**，不是译文的医学准确性）。
